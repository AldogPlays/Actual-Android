# Configuration, browser behavior and privacy

## Connect and configure

On first launch, enter a preferred HTTPS URL and optionally a fallback. Domains, custom ports, overlay-network names, IPv4 and bracketed IPv6 (`https://[fd00::1234]:5006/actual/`) are supported. Paths, encoded path characters and trailing slashes are preserved. Credentials in URLs, fragments and query strings are rejected. Connect displays a reachability review; HTML titles and exact Actual markup are never required. Missing isolation headers and proxy/authentication pages are warnings, not identification failures.

HTTP is available after a native warning, because Android cleartext policy cannot dynamically whitelist arbitrary hosts. HTTP exposes data and generally cannot provide Actual's required secure context, except browser-defined trustworthy loopback cases. Use HTTPS with a certificate trusted by Gecko. Invalid certificates are never ignored. Native probes trust system CAs; Gecko uses its own certificate trust implementation. User-installed private CAs are not opted into automatically. Configure a valid certificate for your hostname.

No toolbar is displayed over Actual. Open settings by **long-pressing the launcher icon → Servers & settings**. A two-finger hold for at least 1.2 seconds, followed by lifting a finger, is also available in the web content. Settings provide URL editing, testing, diagnostics, version information, return to current page, and confirmed browser-data deletion.

## Connection and data safety

Preferred is probed first; fallback is considered for reachability and HTTP failures. TLS failure stops selection for explicit user attention. Authentication and reverse-proxy redirects count as reachable and are reviewed; the probe never sends browser cookies or follows redirects to another origin. Each request has four-second connect/read bounds and at most five same-origin redirects.

Network callbacks debounce for three seconds. An initial failure gets one additional probe; healthy pages are left running. Failed active servers can offer a reachable alternative. There is no timed infinite retry loop and no automatic switch back merely because the preferred host returns. Retry rechecks preferred first. Failover always opens the configured base path, never copies query strings, tokens or route suffixes from another origin.

**Different origins have separate cookies, authentication, IndexedDB and local budgets.** Switching origin requires review and may require logging in and initializing a budget. Local data is never migrated, replaced or cleared by failover. Explicit clearing deletes *all* origins' browser data, including unsynced budgets; synchronize/export first. Uninstalling also deletes local app data.

## Browser lifecycle and navigation

A single non-private GeckoSession and the default app-private persistent Gecko profile retain cookies, IndexedDB, local storage, caches and service workers. The session lives at Application scope to survive Activity recreation without reloading. Activity delegates are detached on destruction and rebound. Saved Gecko session state is put in Android's saved-instance state for process recreation; when unavailable after a cold process restart, the server is reselected while the profile remains intact. Auth-origin approvals are in memory only and must be renewed after Activity recreation. Back gestures use Gecko history, then leave the app. Background/foreground events set the session active state without reloading healthy content.

Top-level navigation stays within the active origin or individually approved authentication origins. Other HTTP(S) origins require a native approval or explicit external-browser action. New-window requests can be approved into the current session; popup/multi-window OAuth that depends on `window.opener` is not supported. Non-HTTP(S) top-level destinations are blocked. This controls navigation, not all subresource networking: your server, scripts and approved identity provider can load their own resources. Gecko enforces same-origin rules, COEP and mixed-content security. Page permissions are denied except persistent storage for the active server. Persistent storage does not replace backups.

System document pickers support file import and confirmed downloads without storage permission. Native alert, confirm, text, basic HTTP auth and HTML choice prompts are implemented. WebAuthn, camera/microphone, geolocation, native date/color prompts and complex popup OAuth are not implemented. Downloads use a generic filename; canceled downloads are not saved. A download in progress may not survive process death. No download service or broad filesystem access is used.

## GeckoView / Actual compatibility

See [compatibility investigation](docs/COMPATIBILITY.md). Diagnostics use a bundled privileged WebExtension with a top-frame native message delegate. Firefox Xray waivers read the **page** global (`window.wrappedJSObject`) rather than measuring the privileged content-script global. The delegate validates session, top-level sender, current active origin and message URL. It returns no secrets or commands to page scripts. It never alters CSP, injects bypasses, trusts invalid certificates, or spoofs `crossOriginIsolated`.

Diagnostics show `isSecureContext`, `crossOriginIsolated`, SharedArrayBuffer, WebAssembly, Worker, IndexedDB, Cache and service-worker API presence, plus the page engine user agent and pinned engine version. Refresh reads the most recently reported result; it does not reload Actual. API presence is not proof of a successful worker/database operation or budget sync. Diagnostics for authentication origins are deliberately not trusted as server diagnostics. A missing/stale result is unverified, not success.

## Privacy

Only `INTERNET` and `ACCESS_NETWORK_STATE` are used as Android system permissions. Gecko media wake-lock and audio-settings permissions are explicitly removed; background media playback is not supported. AndroidX adds a package-scoped signature permission for its non-exported receiver. No Google runtime services, Firebase, accounts, push integration, root or accessibility services are required. AndroidX/Media3 transitive engine dependencies are libraries, not Play Services. Server URL configuration is AES-GCM encrypted using an Android Keystore key in private preferences. Browser profile protection relies on app sandboxing and device encryption; Gecko profile data is not separately Keystore-encrypted. Backups are disabled. No URL, cookie, token or budget logging is added by app code; Gecko console output and remote debugging are off. Debug builds are debuggable by Android and should be used for testing only.

A private bundled runtime configuration disables optional telemetry, Safe Browsing list updates/lookups, add-on updates, push, captive portal/connectivity probes, speculative DNS/prefetch and browser DoH; the supported runtime telemetry observer is notified with `false`. No crash-upload service or Glean SDK initialization is added. The disabled Safe Browsing service means there is no third-party reputation protection: approve only trusted servers/auth origins. Gecko may still use DNS, certificate revocation/OCSP or certificate-related infrastructure, and your pages can contact their own services. A packet-capture audit has **not** been performed; do not interpret these settings as a guarantee of zero engine network traffic. Engine preference names are internal and must be re-audited when upgrading. The private YAML path is explicitly supplied through the documented runtime API; external ADB debug configuration paths are not consumed.
